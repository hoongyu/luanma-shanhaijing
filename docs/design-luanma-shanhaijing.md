## 一、这是什么，为什么做

**一句话**：中文乱码的妖怪图鉴。每一只「字妖」都有名字、形貌、以及**字节级精确、可运行复现**的成因。

**为什么是这个选题**（接回最初的目标：做能商业上线的东西 + 攒开发者自媒体口碑）

调研得出的核心机制是：**产品要自带「可被引用的结论」，而不是自带「功能」**。实测对比——纯工具型 Show HN 普遍 1–20 分（RTK 18 分、Toktrack 2 分、Headroom 2 分）；带结论的内容贴轻松上千分（源码泄露 2,095 分、fake star economy 810 分）。机制差异在于：**工具要人先安装才产生价值，结论只要人读到就产生反应，而且反对者会替你转发。**

这个选题同时满足四个约束，是候选里唯一全中的：

| 约束 | 如何满足 |
|---|---|
| 中国风名正言顺 | 题材就是中文；形式取自《山海经》图鉴体 |
| 视觉有天然位置 | 乱码本身就是视觉素材，不需要发明装饰 |
| 有独家素材 | 作者撞过 UTF-8 字节切片 panic，是被迫 Windows + 中文路径的人，这个约束被全生态系统性忽视 |
| 自带可引用结论 | 每一条都点名一个真实的失败，且可复现 |
| 不出镜、只写字 | **每只妖天生就是一篇公众号推文**，写作与产品是同一件事 |

**首年收入预期：接近零。** 回报形式是口碑与 FDE 岗位的可验证信号。（德国 §16b 学生居留的自雇限制另见主计划文档。）

## 二、产品定义

### 形态

**案例图鉴**（不是诊断器、不是测试套件、不是排行榜）。读者是**被内容吸引来的收藏品心态**，一口气看完，不是带着问题来查。

→ 因此优化美感与传播，不为 SEO 服务。

### 一只妖的解剖：七个字段

| 字段 | 内容 | 备注 |
|---|---|---|
| **名** | 锟斤拷 | 用民间已有的妖名，不自造 |
| **形** | 你实际看到的字符 | |
| **現** | 在哪一层现身 | 编码转换 / 内存 / 字体 / 分词… |
| **因** | **字节级成因** | 必须精确到十六进制。**这是页面的视觉主角** |
| **驗** | ⭐ **可运行的复现代码** | **本项目与「网上乱码大全」的分界线** |
| **異** | 孪生/变体 | 如烫烫烫之于屯屯屯 |
| **驅** | 修法 | |

### 🔴 「驗」字段是整个项目的地基

每条附一段能跑出该乱码的代码，**且全部复现脚本进 pytest、CI 每天跑**。哪天某条考据因环境变化不成立了，测试会红。

> 别人写图鉴靠记忆和转述；**你的每一条都是活的、可执行的、被持续验证的。** 这一条就足够拉开差距。

**收录门槛**：过不了「驗」这一关的不收。宁可少收，不可掺水。

## 三、已验证的考据（字节级复核通过）

决定性证据在 GBK 编码的字节对齐上：

| 字 | GBK 编码 |
|---|---|
| 锟 | `EF BF` |
| 斤 | `BD EF` |
| 拷 | `BF BD` |
| 烫 | `CC CC` |
| 屯 | `CD CD` |

**锟斤拷** — 伤上加伤。文本先错过一次，坏字被换成 U+FFFD，其 UTF-8 为 `EF BF BD`；两枚相连共六字节 `EF BF BD EF BF BD`，按 GBK 双字节切开正是 锟·斤·拷。
> **额外发现**：三枚 U+FFFD 会解码失败（`incomplete multibyte sequence`）——**锟斤拷必须成双**。

**烫烫烫** — MSVC 调试版把未初始化的**栈**内存填为 `0xCC`（int3 断点指令），`CC CC` 在 GBK 中即「烫」。所见非乱码，是**内存本身的颜色**。

**屯屯屯** — 同上，**堆**内存填 `0xCD`。见烫知栈，见屯知堆。

## 四、视觉系统

### 妖形：由该妖自己的字符构成，一笔不画

三条构成法叠加（均无绘画能力需求）：

- **身** 主字最大居中 · **肢** 次字左右镜像成对 · **尾** 末字沉底 · **冠** 主字缩小悬顶成双
- **皮** 十六进制底纹只在妖形内部显现（`EF BF BD` 织在锟斤拷身上）——**真相长在皮肤里**
- 轻度 `feTurbulence` 墨渗，避免字体边缘过于干净

> **概念自洽**：妖就是那几个字，不是字的插图。

### ⚠️ 已知软肋：单字重复型的妖会单调

烫烫烫、屯屯屯、口口口 三个字相同，六个位置只有大小和镜像在变。**必须为这一类单独设计构成规则**（阵列 / 堆叠 / 残缺），不能沿用锟斤拷那套。

### 版式与配色

古籍版式：版框双线、版心带鱼尾、界栏六道、竖排书名。

三色：**宣纸 `#EAE3D5` · 墨 `#171410` · 朱砂 `#A32D22`**。
朱砂只出现在两处——字段名与十六进制。**全页唯一的红色落在真相上。**

### 动效：每个字各有脾气

六个位置六种互不重复的反应（关键帧两两不同，时长 6/6 各异）：

| 部位 | 动作 | 时长 |
|---|---|---|
| 身 | 沉震（压扁再弹回） | .72s |
| 肢左 | 振翅（向外大幅甩） | .62s |
| 肢右 | 急抖（高频小幅） | .46s |
| 尾 | 摆（钟摆四次衰减） | .95s |
| 冠左 | 旋落（飞起打整圈） | .82s |
| 冠右 | 弹跳（只上下不旋转） | .68s |

**肢左肢右刻意不做镜像** —— 镜像看着是两个动作其实是一个，戳一次就知道另一边长什么样。

其余：回弹曲线 `cubic-bezier(.34,1.56,.64,1)`；妖形 5.4s 呼吸循环；点击墨滴晕开；条目六行错峰滑入；字节块逐个弹入。

**交互规则**：展开后再戳只播动画，**不合页**。妖是可以反复戳的，翻页是另一回事（闔卷 / ESC / 点另一页）。

### 文案

- **说明用现代汉语**，文言只留给字段名与书名（版式的一部分）
- 成因压到 **70–80 字**，每条注 15 字上下
- 正文无衬线、`88%` 墨色、14.5px —— 楷体小字号在屏幕上会糊

## 五、字体决策（实测数据，非推测）

### 分工由实测决定

| 用途 | 字体 | 授权 | 子集 | 竖排支持 |
|---|---|---|---|---|
| **妖形 + 妖名**（横排） | 马善政毛笔楷书 → CSS 名 `YaoBrush` | SIL OFL 1.1（原文已直读） | **2,848 B** / 7 字 | ❌ 无 `vhea`/`vmtx` |
| **竖排版式** | 源流明體 TW-R → CSS 名 `YaoSeal` | SIL OFL 1.1 | **9,552 B** / 39 字 | ✅ `vert,vhal,vpal,halt,palt` |
| **说明正文** | 系统无衬线栈 | 仅 `font-family` 引用，不分发文件 | 0 B | — |

**整页字体总量 12.4 KB**（原始字体 5.59 MB + 15.5 MB）。

### 🔴 三条不能违反的规则

1. **马善政绝不可用于竖排** —— 实测完全无竖排度量表，句号逗号不会移到右上角
2. **`pyftsubset` 必须带 `--layout-features="*"`** —— 网上教程常写 `--layout-features=""`，会**静默毁掉竖排标点**
3. **子集化在 OFL FAQ 2.6 下算 modification，必须改名** —— 故 CSS family 用 `YaoBrush`/`YaoSeal`。原始 OFL 全文归档于 `fonts/LICENSES/`

### ❌ 已排除（附理由）

| 字体 | 排除理由 |
|---|---|
| **Windows 隶书 / 宋体 / 楷体** | 只有 Windows 有，跨平台大面积回退。且微软 FAQ 明禁「逐字提取轮廓」——**「转 SVG 素材库」这条绕行方案不成立**；但**出整幅图合法**（可用于公众号配图） |
| **方正全系** | 官网明写嵌入网站属「内置使用」，**不在免费授权范围**，且「格式转换后」五字堵死 woff2 辩解。方正维权最活跃 |
| **HarmonyOS Sans / OPPO Sans / vivo Sans / MiSans** | 均只授权「未修改副本」，禁改编 → 子集化出局。OPPO 另禁「提供其他下载渠道」→ 自托管与开源分发均封死 |
| **字酷堂全系** | 个人免费，商用需付费 |
| **站酷高端黑 / 酷黑** | 无可引用授权全文，修改权从未授予 |
| **霞鹜篆书** | 授权干净但**仅 75 字，本项目用字 0/9 覆盖**。仅可做印章点缀 |
| **京华老宋体** | 视觉最对，但作者原文（知乎）**HTTP 403 无法直读**，两份报告结论互相矛盾。**未取得原文前不得开工** |

### ⚠️ Google Fonts CDN 绝对不用

慕尼黑地方法院 2022-01-20 判决（LG München I，案号 3 O 17493/20）：远程引用 Google Fonts 违反 GDPR，**判赔访客 100 欧元**，继续违规可处最高 25 万欧元罚款。法院驳回「正当利益」抗辩的理由正是「字体完全可以自托管」。

**作者常住德国，这是其所在辖区的直接风险**（在中国大陆不可达只是次要问题）。→ 一律自托管。

### 隶书：穷举后确认「不存在」（2026-08-12 专项核查）

不存在同时满足「商用 + webfont 嵌入 + 子集化」且覆盖够用的隶书中文字体。池子已清空：ZeoSeven 1247 款仅 4 命中、猫啃网 833 款仅 2 命中、Google Fonts 零 CJK 隶书、台湾全字库只出正宋體与正楷體。

| 候选 | 授权 | 卡点 |
|---|---|---|
| 教育部標準隸書 v3.00 | CC BY-ND 3.0 TW | 字形最正统，商用+嵌入合法，但**禁子集化**；繁体 4808 字，**缺「锟」「烫」「錕」**——图腾字缺失，致命 |
| 阿里妈妈刀隶体 | 阿里声明（**UNVERIFIED**，官方页读不到原文） | **唯一覆盖「锟斤拷烫屯」**（GB2312 全集），但明文禁「拆分」；爨宝子碑刀刻方笔，非曹全碑舒展感 |
| UnYetgul（韩国） | GPL v2（无 font exception） | **唯一可子集化**，字形比教育部版更有气势；但简体覆盖 55.6%、缺 4 个目标字、copyleft 灰区 |
| USMCC 洄波隶书 | **CC0**（三门槛全过零风险） | **仅 308 字，0/7 覆盖**。作者在持续更新，值得放进观察列表 |

**结论：马善政不是次优选择，是唯一选择。**

> ⚠️ **纪律验证案例**：曺全碑隸 CoQuBeLi 被 ZeoSeven 标为「商业使用 允许 ✅」，而作者协议原文写「用于商业用途请告知我以单独获得许可」——需逐案授权。**第三方字体站的标注不可采信，必须回原始授权源。**

**若将来需要隶书**：两条路都要求**整份原样上传、不子集化**（教育部版 ~3.2 MB / 阿里版 ~4-5 MB，配 `font-display:swap` 且只在标题层加载）。阿里版落地前必须先从官方下载包里抠出《字体使用规范》PDF 自读。

### 可用备选（授权已核实为三项全绿）

霞鹜文楷（**唯一明文豁免「子集化须改名」义务的字体**）、思源黑体/宋体、文津宋体（生僻字兜底）、全字庫正楷體、寒蝉正楷体、站酷小薇/快乐体/庆科黄油体（走 Google Fonts 的 OFL 发行版）。

## 六、技术架构

```
妖谱（YAML，一妖一条）
   ↓
复现层（Python，每妖一个函数）──→ pytest 断言其确实产出该乱码 ──→ CI 每日跑
   ↓
构建期：抽取用字 → pyftsubset 子集化（--layout-features="*"）
   ↓
Astro 静态站 → Cloudflare Pages
   ↓
同一套资产出 PNG → 公众号配图
```

**已跑通并验证的**：
- `redact.py` / `parse.py`（sessionprint 遗留，5 个测试）—— 与本项目无关，另行处置
- 子集化工具链在 Windows 全程可跑，**无任何环节需要 macOS**（fontTools 4.63.0 + Brotli 均有 cp314-win_amd64 wheel）

**Cloudflare Pages 约束**（官方核实）：单文件上限 25 MiB；免费版 20,000 文件；**静态资源请求免费且无限**，不计入配额。缓存头走 `public/_headers`：`/fonts/* → Cache-Control: public, max-age=31536000, immutable`。

**加载策略**：版式字体 `font-display: block` + `preload`（子集仅 9.5 KB，避免版式跳动）；正文 `swap`。

**⚠️ Astro 坑**：实验性 Fonts API 的 `subsets` 不含 CJK，且 v5.16.13 的 `getFontBuffer()` 处理 CJK 有内存泄漏（已于 2026-01-29 修复）。**建议绕开，用独立 npm script 在 `astro build` 前跑完子集化。**

**⚠️ 破折号**：不写 `lang="zh-Hans"`，思源系列会把 U+2014 渲染成贴基线的西文短横。

## 七、内容与发布节奏

**每只妖 = 一篇公众号推文**，图鉴是合集，公众号是首发地。写作与产品同一件事。

> ⚠️ 写第一篇之前**必须先读 `mandao` skill**（「慢刀」公众号的总管）。不读，写出来的会是一篇通用的、正确的、但不是这个号的东西。

**渠道优先级**：① 被诊断工具的 GitHub issue 区 → ② 公众号（结论的中文首发）→ ③ V2EX 分享创造 → ④ Astro 站点（英文沉淀）→ ⑤ Show HN（**发结论不发工具**）

**首批目标 12–15 条**，全部过「驗」关。
